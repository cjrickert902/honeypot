01 — The bait

Something sweet, left out in the open.

A honeypot is a server built to be attacked. It pretends to be a real machine — an SSH login, a Telnet prompt, a WordPress admin page — and quietly writes down everything that touches it.

02 — The swarm

The bots don't take long.

Our hypothesis: the first password guess lands within an hour of going online, and the first request for a leaked /.env file within a day. The honeypot goes live next — its real numbers will replace this sentence.

03 — The lock

Then we check the doors they try.

Every path the bots probe for — /.env, /.git, forgotten backups — becomes a check in our scanner. It grades a business website in plain English, using only public information unless the owner signs off in writing.

04 — So far

It works. We tested it.

100% vs 30%

Precision on exposed-file checks: reading the file's contents, versus trusting the status code like simple scanners do. Seven lab sites, 25 planted flaws.

F → D

Our own website, 35 to 60 out of 100, after one deploy of security headers. Two DNS records away from an A.
