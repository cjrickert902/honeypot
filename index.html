01 — The bait

Something sweet, left out in the open.

A honeypot is a server built to be attacked. It pretends to be a real machine — an SSH login, a Telnet prompt, a WordPress admin page — and quietly writes down everything that touches it.

Nobody has a legitimate reason to connect to it. So every single connection is a scan or an attack.

03 — The lock

      
Then we check the doors they try.

      
Every path the bots probe for — /.env, /.git, forgotten backups — becomes a check in our scanner. It grades a business website in plain English, using only public information unless the owner signs off in writing.

    05 — The rules we play by
    
      
    Hacking-adjacent, done honestly.
    
      
    
        
    01
    Public by default
    The study only reads what any visitor's browser already sees: DNS records, one TLS handshake, one homepage load.
    
        
    02
    Permission in writing
    Checks for exposed files like /.env refuse to run without a signed, unexpired authorization from the owner.
    
        
    03
    Nobody gets named
    Regional results are reported in aggregate. No small business ends up on a list of weak sites.
    
        
    04
    Malware stays caged
    Files attackers download never leave the honeypot server. Only their SHA-256 fingerprints come home.
